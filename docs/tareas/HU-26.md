## Qué hacemos (188)

- Cambiar solo el cuerpo de `registrar_evento()`: además del log, crea el `EventoAuditoria`. **La firma no cambia**: quienes ya la llaman no se tocan.
- Guardar `detalles` ya pasado por `limpiar_detalles()`; nunca el dato original.
- Leer el user agent de `request.META["HTTP_USER_AGENT"]` (vacío si no hay `request`).
- Si la escritura a la tabla falla, el flujo que llamó **no se rompe**: se deja el error en el log y se sigue.
- Prueba mínima: se crea la fila, el `password` queda como `***` y un `request` ausente no truena.

**Avance sin la 187:** se puede dejar listo todo lo anterior (lectura de IP y user agent, enmascarado, manejo de fallo) y cerrar la escritura a tabla cuando exista el modelo.

**Fuera de alcance de la 188:** agregar llamadas a `registrar_evento()` en los flujos de otras historias (login, registro, recuperación, etc.). Cada historia agrega la suya; la 190 comprueba que existan.
